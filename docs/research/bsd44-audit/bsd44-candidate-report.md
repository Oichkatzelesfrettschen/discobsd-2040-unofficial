# Discobsd 4.4BSD-Lite2 backport candidate ledger

This is a read-only comparison of `~/Github/discobsd-pico-unofficial` at
`b40c1c4fd5032ada8b651588645f33c8f856c985` against the authority checkout
`~/Github/4.4BSD-Lite2` at `b10da34408c8a0f32f51d79a7f16bd75337115d2`.
The RP2040 boundary is Cortex-M0+
Thumb-1, no MMU, an MPU fencing the user window, static libc linkage, a 96 KB user process window,
and user Thread mode with `CONTROL[0]=1`. The ledger records candidate
surfaces, not authorization to change the target tree.

Evidence commands included `rg`/`git grep` for callers and declarations,
Universal Ctags/readtags, cscope, cflow, ast-grep, semgrep, cppcheck,
clang-tidy, Coccinelle `spatch`, cloc, scc, lizard, cross-gcc compilation,
`arm-none-eabi-size`, `arm-none-eabi-nm`, `arm-none-eabi-readelf`,
`arm-none-eabi-objdump`, radare2, Rizin, pahole, jq, and diffoscope. The
resulting logs and objects are retained under this directory.

## Rejected or bounded surfaces

`fgetln()` and `fpurge()` depend on the 4.4BSD stdio layout (`_r`, `_p`, and
line-buffer fields) rather than Discobsd's `_cnt`/`_ptr`/`_base` layout.
`fgetpos()`/`fsetpos()` lack a public `fpos_t`. `funopen()` would require a
`FILE` redesign. `glob()` (590 cloc), `radixsort()` (224 cloc), and locale
support exceed the process-window and fixed-C-locale budget. `mmap()` and
Berkeley DB require an MMU/vnode/page-cache architecture. Networking tools
require a missing mbuf stack. These are bounded rejections, not claims that
the wider POSIX or BSD domains are complete.

The previously landed `<err.h>`, `<sys/queue.h>`, `vis()`/`unvis()`,
`fmt(1)`, `heapsort()`, `bsearch()`, `fnmatch()`, `column(1)`, and
`getcwd()`/`realpath()` surfaces are therefore excluded from the remaining
candidate rows.

## RP2040 privilege boundary

`sys/arch/rp2040/rp2040/locore0.S:155-162` loads `CONTROL=3` before entering
user mode. Bit zero selects unprivileged Thread mode and bit one selects PSP.
The same source enables interrupts with `cpsie i` before writing CONTROL.
`sys/arch/rp2040/include/intr.h:17-20,122-132` records that ARMv6-M has only
all-or-nothing PRIMASK and that the mask helpers execute `cpsid i`/`cpsie i`.
CMSIS privilege rules make those instructions privileged. Therefore a
userland shim cannot mask hardware interrupts or safely claim interrupt
ownership. Any 4.4BSD source that relies on `sigprocmask()` to close a
kernel-critical race must be redesigned around an atomic kernel operation,
not copied into libc.
