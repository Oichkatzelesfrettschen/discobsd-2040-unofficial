1. `sys/arch/rp2040/rp2040/swapram.c:306-307` and `sys/arch/rp2040/rp2040/swapram_in.c:302-305` (via `e_res=0` from `swapram_commit`): zero-byte images can reach `swapram_pool_free(..., size=0)`, which returns `-1` and panics on swapin.  
Consequence: process swapin path can wedge kernel on empty/zero-compressed images.  
Minimal fix: guard `if (e->e_res == 0) skip free;` in `swapram_in`, or enforce non-zero minimum reservation and never set `e_res` to zero.

2. `sys/arch/rp2040/rp2040/swapram_pool.c:86` (`off + want > mp->p_size`): arithmetic is overflow-prone on 32-bit `unsigned int`.  
Consequence: with large/corrupt `(off, size)` arguments, overflow can bypass bounds and corrupt allocator metadata, enabling pool-state corruption and invalid frees.  
Minimal fix: replace with overflow-safe check: `if (off > mp->p_size || want > mp->p_size - off) return -1;`.

3. `sys/arch/rp2040/rp2040/swapram.c:141-187` (`sr_expand`) plus `swapram.c:298-305`: expansion success is keyed only on output length, not compressed-input consumption/valid end-of-stream.  
Consequence: corrupt/garbage compressed payload can still pass with correct `rlen`, leaving stale bytes and silently restoring a possibly wrong image image; integrity risk.  
Minimal fix: after finish, verify decoder consumed exactly `clen` bytes (and optionally reject `HSDR_POLL_MORE` terminal states that imply truncation/mismatch).

4. `sys/arch/rp2040/rp2040/swapram.c:245-249` (`swapram_put`) and `sys/arch/rp2040/rp2040/swapram_pool.c:140-145` (`trim`): codec failures are escalated to panic, and on failure there is no rollback API to free/reclaim the reservation in `swapram` path.  
Consequence: allocation churn can become unrecoverable on unexpected codec behavior; kernel stability degrades by hard panic instead of controlled fallback.  
Minimal fix: thread failure returns through `swapram_put/swapram_commit` and free the reserved block to allow transparent flash fallback.

5. `sys/arch/rp2040/rp2040/swapram.c:47-50`, `65-67`, `71`, and hot-path calls (`swapram_out`, `swapram_put`, `swapram_in`): global static pool/map/encoder/decoder/tables are unprotected and shared across calls.  
Consequence: any re-entrant call (nested swap paths, IRQ-level callability concerns, or future SMP enablement) can race and corrupt compressed state or slot metadata.  
Minimal fix: serialize all swapram out/in operations (spinlock + non-blocking section), or per-CPU/context-localizing those state machines.

6. `sys/arch/rp2040/rp2040/swapram.c:209` plus `sys/arch/rp2040/rp2040/swapram_pool.c:47-58`: per-process worst-case full-image reservation can be wasteful and first-fit can fail despite sufficient total free space under fragmentation.  
Consequence: avoidable misses of RAM tier cause flash fallback, increasing latency/wear on NOR while RAM remains available.  
Minimal fix: reduce worst-case over-reserve or use allocator guidance (`swapram_pool_largest`)/compaction to reduce false-negative allocations under fragmentation.
