FOURFALL CLEAN-ROOM COPYING RE-REVIEW
======================================

VERDICT: NEEDS CHANGES

The implementation rework resolves the previous palette finding and the three
stored base-row findings in fourfall.c and its tests. The complete review
package remains unclean for two reasons. First, ff_cells() rotates the revised O
base order back into the legacy program's exact O-row order at orientation 2.
The O geometry is forced, but the enumeration order is selectable and
unobservable. Second, the canonical clean-room specification still prescribes
the legacy-correlated palette and retains the three legacy-correlated ordered
rows. The implementation record now documents the revised choices, but its
claim that all 132 vectors were transcribed verbatim is false for the 28 revised
SHAPE lines.

The normalized 16-token result passes the specified rejection gate: Fourfall
shares 62 of 5,384 candidate runs, or 1.2 percent, against a 5 percent rejection
threshold. The fixed-string, exact-string, algorithm-fingerprint, and
game-facing trade-dress searches otherwise support clean-room independence.

Findings that require changes
-----------------------------

F1 -- the source palette changed, but the authoritative specification did not

New: docs/research/falling-block-clean-room-spec.md:67-69
Resolved implementation: games/fourfall/fourfall.c:620-624;
games/fourfall/tests/play.py:302-323; games/fourfall/tests/mutants.py:141
Original: legacy/non-arm/mips-pic32/share/examples/gpanel/tftetris.c:315
Classification: EXPRESSIVE.

The new source maps I white, O blue, T green, S magenta, Z cyan, J red, and L
yellow. Every semantic assignment differs from the original, so the source and
its color assertions resolve previous finding F1. The specification still maps
I cyan, O yellow, T magenta, S green, Z red, and J blue, the same semantic
assignments as the original for six pieces. Seven console colors constrain the
set but do not force its 7-factorial piece permutation.

Suggested rewrite: update specification lines 67-69 to the implemented palette
and state that the palette supersedes the first review draft. Keep monochrome
mode unchanged.

F2 -- the revised O base row rotates back into the legacy ordered row

New: games/fourfall/fourfall.c:103,143-156;
games/fourfall/tests/vectors.txt:5-8;
docs/research/falling-block-clean-room-spec.md:54,285-288
Original: legacy/non-arm/mips-pic32/share/examples/gpanel/tftetris.c:272
Classification: FORCED GEOMETRY, EXPRESSIVE ORDER.

The stored O row at fourfall.c:103 is reverse row-major and resolves the exact
stored-row match reported previously. Applying the uniform matrix rotation
twice produces (0,0),(0,1),(1,0),(1,1), exactly the legacy line order. The O
cell set is a public mechanic, but the order in which an implementation returns
four indistinguishable cells is selectable. The SHAPE harness sorts both sides,
so its passing result does not test this expression-level ordering. The
specification also retains the original row-major text at lines 54 and 285-288.

Suggested rewrite: choose an O base enumeration outside the four-order rotation
orbit of the legacy row, for example (1,1),(0,0),(1,0),(0,1), then update the O
SHAPE listings, tests, and implementation record. An alternative complete fix
can preserve reverse row-major order while making ff_cells() keep the O cell
enumeration fixed across rotations. Update the specification in the same
change.

F3 -- the Z source row changed, but the specification retains the old order

New: games/fourfall/fourfall.c:106; games/fourfall/tests/vectors.txt:17;
docs/research/falling-block-clean-room-spec.md:57,297
Original: legacy/non-arm/mips-pic32/share/examples/gpanel/tftetris.c:278
Classification: FORCED GEOMETRY, EXPRESSIVE ORDER.

The source and test now use reverse row-major order, and independent comparison
finds no derived Z orientation that repeats a legacy orientation in line order.
The source therefore resolves previous finding F3. The specification retains
the raw ordered list (0,0),(0,1),(1,1),(1,2), which matches original line 278.

Suggested rewrite: rewrite the specification's Z base and SHAPE rows in the
implemented order, while preserving the same unordered cell sets.

Commercial name and trade-dress review
--------------------------------------

A case-insensitive, binary-safe whole-word search finds Tetris nowhere under
games/fourfall, including source, strings, tests, and Python bytecode. The game
tree also contains none of the original URL, joystick prompt, device paths,
bitmap font, gradient, music, logo, or commercial title.

The specification necessarily names Tetris at lines 26, 569, and 573 to state
the prohibition and record the reviewer checklist. Those occurrences are
review evidence, not game branding. The implementation record names only the
legacy filename tftetris.c at lines 7 and 285 for provenance. Neither document
presents the commercial name as Fourfall's name.

The implemented presentation uses FOURFALL, a left-side ASCII board, a
right-side text panel, and a palette whose seven semantic assignments all
differ from the original. The original uses a right-side pixel board, a
left-side panel, a bitmap font, a gradient, a commercial title, a URL, and
joystick prompts. The generic state labels LEVEL, LINES, NEXT, and GAME OVER do
not reproduce that overall presentation. The stale specification palette in
F1 remains a tracked trade-dress risk and prevents a clean package verdict.
