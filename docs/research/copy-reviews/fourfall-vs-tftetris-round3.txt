Documentation precision advisory
--------------------------------

A1 -- SHAPE rows are canonical cell-set listings, not ff_cells() output order

New: docs/research/fourfall-implementation.md:36-39,127-132
Original: no corresponding reference text
Classification: NOT A COPYING OVERLAP; DOCUMENTATION PRECISION.

The implementation record says rotated orientations inherit base-cell identity
order, which ff_cells() does, and then says SHAPE rows were rewritten "in the
same order." Seventeen of the 28 SHAPE textual rows use a canonical last-row-
first listing that differs from ff_cells()'s identity-preserving output order.
The harness intentionally sorts both sides. The specification correctly calls
SHAPE entries cell sets, and ordered comparison finds zero reference matches
for either representation, so this ambiguity does not weaken the clean verdict.

Suggested rewrite: state that SHAPE rows list each unordered cell set in a
canonical last-row-first order, while ff_cells() preserves base-cell identity
order through matrix rotation and keeps the O order fixed. Keep the separate
order-sensitive O check.
