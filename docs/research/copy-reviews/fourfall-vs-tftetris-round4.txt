FOURFALL CLEAN-ROOM COPYING THIRD RE-REVIEW
============================================

VERDICT: NEEDS CHANGES

The Fourfall source and tests pass the copying comparison. The review found no
copied expressive identifier, literal, comment, ordered shape row, algorithm
fingerprint, presentation structure, or normalized token span. The prescribed
16-token comparison reports 48 of 1,791 candidate runs, or 2.7 percent, below
the 5 percent rejection threshold. A comment-safe use of the same tokenizer
reports 64 of 6,106 runs, or 1.0 percent. Manual review classifies every span
as public tetromino geometry, ordinary C syntax, required headers, generic
array syntax, or independently selected values erased by normalization.

The clean-room package nevertheless needs three documentation/tooling changes:

1. docs/research/fourfall-implementation.md:160 spells the commercial name in
   a legal-case citation. The game tree has zero occurrences, but the literal
   documentation prohibition therefore fails.
2. The reviewer-only independence table at
   docs/research/falling-block-clean-room-spec.md:636,645,647,687 describes the
   superseded 10-by-20/color design rather than the current 12-by-22 textured,
   grayscale-default presentation.
3. The required shingle script at
   docs/research/falling-block-clean-room-spec.md:741-745 removes // comments
   before recognizing strings. The S-piece glyph literal "//" at
   games/fourfall/fourfall.c:393 therefore truncates the token stream and makes
   2.7 percent an incompletely lexed measurement.

Those defects do not identify copying in fourfall.c. They prevent a CLEAN
verdict for the complete code-plus-documentation clean-room package under the
request's literal name and reproducibility gates.

Scope and evidence boundary
---------------------------

The review read the complete 922-line GPLv2-or-later reference, the complete
1,332-line Fourfall source, all text tests under games/fourfall/tests, the two
retained generated test artifacts, both parts of the clean-room specification,
the implementation record, and the prior Round 3 report. The review used no

The only new files written by the review are this report and retained checker
artifacts under the requested scratchpad. The final repository preservation

F3 -- the prescribed lexer consumes a valid glyph string as a comment

New: games/fourfall/fourfall.c:389-394
Original: no corresponding original string; checker at specification:741-745
Classification: REPRODUCIBILITY DEFECT; not candidate copying.

The checker strips // comments before it tokenizes string literals. The literal
"//" is valid C data, but the regex deletes the rest of that source line and
changes the denominator from 6,106 intended runs to 1,791 reported runs.

Suggested rewrite: lex comments, strings, character literals, identifiers, and
operators in one left-to-right pass so comment markers inside literals remain
data. Add a calibrated candidate containing "//", "/*", escaped quotes, and
character literals. Retain the renamed-copy and unrelated-program controls.
