CuteMouse on the i86 serial mouse, host build, by hand
=======================================================

What it shows: a stock DOS mouse driver finds the emulated COM1 mouse by
itself, installs on interrupt line 4 in Microsoft mode, and reports the
movements and buttons the PicoCalc mouse keys make through interrupt 33h.

Disk:

  PYTHON=python3 sh docs/research/i86-dos-emulator/mkdosdisk.sh \
      usr.bin/i86/i86-host svdos-1.44M-disk-1.img c.img 4 CTMOUSE.EXE MT.COM

Session: usr.bin/i86/i86-host -c 286 -s page -h c.img on a
pseudo-terminal, real clock. Each key was typed 0.6 s after the text
before it appeared:

  ctmouse Enter, mt Enter,
  Control-\ (mouse keys on),
  Right, Right, Right, Down, then four Right in one write,
  [ ] { Right { , then q (MT leaves; q is not a mouse key),
  Control-\ (off), Control-] q (leave the emulator).

Reading:

  - Install: CTMOUSE probes, finds the Microsoft mouse at COM1 and line 4.
    After install the modem control register reads 0Fh: DTR, RTS, OUT1
    and OUT2. CTMOUSE writes the line and modem control registers with
    one word to port 3FBh; before the machine split a word access into
    two byte accesses, OUT2 stayed off and no report reached the driver.
  - Reset: two buttons; the pointer at (320, 96), the middle of the
    640 by 200 virtual screen of an 80-column text mode.
  - Each Right tap moves the text pointer 16 virtual pixels (two
    columns), the Down tap 8 (one row), at CTMOUSE's default speed.
  - The four Right arrows in one write are a repeat (8, 16, 32 and 64
    mickeys); CTMOUSE accelerates further and clamps at x = 278h, the
    last column.
  - [ reports button 1 and its release, ] button 2 and its release, {
    holds button 1 until the second {. The Right between them moves
    nothing visible because the pointer is at the right edge.

Not covered: the panel display (-g), the kernel and the board; Windows
3.0's own mouse driver.
