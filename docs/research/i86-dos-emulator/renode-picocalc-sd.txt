Renode runs of usr.bin/i86 on the PICOCALC_SD kernel, 2026-11-20

Kernel PICOCALC_SD (unix-PICOCALC-SD.uf2) with the 32 MiB SD root built by
"bmake MACHINE=rp2040 picocalc-sd-system", which carries the whole install
tree and so /usr/bin/i86. Two files were added to the install tree for
these runs and are not part of the tree: /guest.img (tests/guest.hexdump
padded to 360 KB) and /svmin.img (the SvarDOS boot floppy that
mksvardos.sh makes from the SvarDOS 20250427 360 KB disk 1). The card is
the "tmp" layout of tools/renode/check-picocalc-sdroot.py: the root in MBR
slot 3 (type b7) and an 8 MiB type-ba entry that /etc/rc.rp2040 mounts at
/tmp, where the emulator puts its page file by default. Renode
1.17.0+20260907gitf1dd1b4af with the tree's RP2040 models, the SD card
model, the ST7365P panel model and the keyboard controller model; commands
are typed through the keyboard model and the lines below are the panel's
frame decoded to text by tools/renode/picocalc_fb.py (53 columns: longer
shell lines wrap). Class of evidence: Renode. Virtual times are Renode's
and say nothing about the board's speed; the models have no PSRAM.

==== Run 5: the panel display, i86 -g, the stages of usr.bin/i86/tests/panel.asm
==== (source: the commit that adds this run)

with "i86 -g -a /panel.img" (stage 2 with -w 40), its digit typed on the
keyboard model, and the panel model's frame written with "sysbus.spi1.lcd
DumpPpm" while the guest stood halted. The frame was compared with the one
usr.bin/i86/tests/panel.py computes for the stage, each color component
reduced to the 5, 6 and 5 bits the panel's two-byte format carries, over
all 320 by 320 pixels:

==== Run 8: the panel read back at Control-] (-P) after a text scroll
==== (source: branch usr.bin/i86-panel-capture on main d0e39fa36)

program (tests/panel.hexdump, padded to 360 KB) added to the root as
/panel.img. Typed: i86 -g -P /tmp/cap.ppm -a /panel.img, then '<' (stage
