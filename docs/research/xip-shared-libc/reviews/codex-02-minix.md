1. **Blocker -- “sharing libc is worth an order of magnitude of storage by MINIX’s own estimate.”** The cited MINIX page says only that dynamic linking made `/bin` and `/usr/bin` “10x smaller”; the figure excludes shared-library storage and covers every shared library, not libc alone. The same page states that MINIX did not share library or executable pages between processes ([MINIX 3.2.0 wiki](https://wiki.minix3.org/doku.php?id=releases:3.2.0:usersguide:usingsharedlibraries), “VM”). Independent summation of `relink-results.txt` produced 544,295 static bytes versus 335,360 prototype bytes across 27 successes -- a 38.4% reduction before adding the 32,448-byte shared image -- with three failures. Correction: retain “10x smaller program directories” as a historical MINIX observation; use the bounded DiscoBSD measurement, shared-image cost, and failures for DiscoBSD estimates.

2. **Major -- “MINIX’s dynamic path rests on an MMU ...” as evidence against PIC plus relocation.** `minix/lib/libexec/exec_elf.c:200-275` shows MINIX’s page-oriented implementation, while `:263-299` also contains an allocate-and-copy fallback. MINIX’s chosen loader architecture does not establish that relocation intrinsically requires an MMU, multiple resident address spaces, or page-granular mapping. A DiscoBSD loader could relocate into its single fixed SRAM window. Correction: describe MINIX as one MMU-based implementation, then measure or prototype DiscoBSD relocation costs separately.

3. **Major -- “a flash root is where a missing library is fatal.”** The wiki’s failure mode is absent `ld.elf_so` or a shared-library file. Flash storage does not create that dependency, and immutable or atomically packaged flash may reduce the deletion risk. The stream never establishes that the proposed relocating design stores independently mutable files, while the fixed-address design “kept together with the boxes” receives favorable packaging by assumption. Correction: compare both designs under the same packaging and corruption model.

4. **Major -- “No crunchgen or multicall in MINIX sources.”** The grep searched only `minix/`. The full source tree contains `distrib/common/Makefile.crunch:3-74`, `share/mk/bsd.own.mk:499,625`, and installed `crunchgen` entries in `distrib/sets/lists/comp/mi`. The narrower observation survives: the MINIX-specific subtree and `minix/drivers/storage/ramdisk/Makefile:33-103` do not invoke crunchgen and list separate programs. Correction: state that MINIX retains NetBSD crunchgen infrastructure but its inspected MINIX images do not use it.

5. **Major -- the prototype rows cannot be replayed from the retained measurement bundle.** `measure/relink_against_libcx.sh:9` requires `elf32-arm-x.ld` and `libcx.syms.elf`; `rg --files measure` lists neither. The script also consumes preexisting object files rather than recording their hashes. `sh -n` and `shellcheck -S error` pass, but syntax cleanliness cannot recover missing linker inputs or provenance. Correction: retain both generated inputs, their generation command, object hashes, tool versions, and a checksum-verified replay command.

6. **Major -- “static PIE is unsupported.”** The cited exec code does not prove that absolute statement: `exec_elf.c:35-37` accepts `ET_DYN`, and `:213,313` applies a load offset. The build system supplies narrower evidence: `share/mk/bsd.README:350-352` defaults `MKPIE` to `no`, and `share/mk/bsd.sys.mk:181-186` withholds PIE flags for static links. Correction: say the inspected default build does not produce static PIE; reserve “unsupported” for a failed, recorded static-PIE build and execution test.

7. **Minor -- “bin and sbin ... force `-static`.”** `share/mk/bsd.own.mk:14-15` and both `Makefile.inc` files use `?=`, so they establish overridable defaults rather than force a value. The ramdisk’s `LDSTATIC == "-dynamic"` branch confirms an intended override path. Correction: replace “force” with “default to.”

8. **Minor -- “MINIX 1/2 shared text.”** The repository’s `v3.1.3:servers/pm/exec.c:114,243-266` still contains `find_share`, so the mechanism survived into MINIX 3. Commit `c078ec0331` introduced paging and removed the old sharing path; the 3.2.0 wiki later reports absent page sharing. Correction: say pre-paging MINIX through 3.1.3 shared separate-I&D text by inode, device, and ctime; paging replaced that mechanism.

The static-default source findings, historical wiki quotations, userspace dynamic relocation path, separate ramdisk programs, and historical `find_share` mechanism survive. The comparative conclusion does not: MINIX supplies useful historical mechanisms, but it neither falsifies a non-MMU relocating loader nor demonstrates a tenfold DiscoBSD libc saving. The deciding evidence remains a replayable, equal-packaging comparison that includes the shared image, loader and relocation bytes, SRAM reservation, all link failures, startup latency, and RP2040 XIP-cache behavior.
