1. **Major -- false multicall claim.** Claim: “no busybox-style multicall in base” ([03-illumos.md](streams/03-illumos.md:33)). Evidence: current illumos commit `f0c8390b` dispatches by invocation basename in [`alias.c:219-244`](https://github.com/illumos/illumos-gate/blob/f0c8390bf3dce936fdac44978ddeb9c12a65f84d/usr/src/cmd/ast/ksh/builtins/alias.c#L219-L244); its [Makefile](https://github.com/illumos/illumos-gate/blob/f0c8390bf3dce936fdac44978ddeb9c12a65f84d/usr/src/cmd/ast/ksh/builtins/Makefile#L31-L60) names 28 aliases, and the [package manifest](https://github.com/illumos/illumos-gate/blob/f0c8390bf3dce936fdac44978ddeb9c12a65f84d/usr/src/pkg/manifests/shell-ksh93.p5m#L43-L83) ships hardlinks such as `cmp`, `cut`, `tee`, and `wc`. Correction: describe this installed multicall wrapper separately from in-process ksh builtins and `isaexec`.

2. **Major -- the PIC register cost is generalized from an optional mode.** Claim: “PIC data access costs a base register and an indirection” ([03-illumos.md](streams/03-illumos.md:43)). Evidence: piping `extern int shared_value; int read_shared_value(void){return shared_value;}` into GCC 16.2.0 with `-mcpu=cortex-m0plus -mthumb -Os -fpic -S -o -` produced PC-relative GOT construction using `ldr`, `add r3,pc`, and caller-clobbered registers, without reserving `r9`. Only adding `-msingle-pic-base -mpic-register=r9` selected a dedicated base register. ARMv6-M also has PC-relative literal loads and address formation. Correction: compare measured default GOT construction, single-base PIC, and fixed-address code across the actual boxes; retain the extra GOT load as a measured cost rather than asserting a universal register tax.

3. **Major -- the runtime-linker analogy misstates both the operation and its contract.** Claim: `_setup.c` stores `ld_base + r_addend`, therefore “a fixed-window exec loader could use the same RELATIVE-only rule” ([03-illumos.md](streams/03-illumos.md:28)). Evidence: [`_setup.c:273-285`](https://github.com/illumos/illumos-gate/blob/f0c8390bf3dce936fdac44978ddeb9c12a65f84d/usr/src/cmd/sgs/rtld/amd64/_setup.c#L273-L285) says both RELATIVE and JMPSLOT remain and executes `*target += ld_base + r_addend`; the preexisting target word matters. Its untyped loop works only because ld.so.1 has a special protected-symbol link contract. Correction: specify the ARM relocation format, symbol-binding model, bounds/alignment validation, unsupported-type rejection, and references among executable code, libc text, and per-process data.

4. **Major -- the retained relink experiment does not establish one clean shared copy.** Claim: “one stored copy of libc text” and “the relocation loop can be tiny” ([03-illumos.md](streams/03-illumos.md:40)). Evidence: [relink_against_libcx.sh](measure/relink_against_libcx.sh:9) requires absent `elf32-arm-x.ld` and `libcx.syms.elf`. [relink-results.txt](measure/relink-results.txt:1) records three failed programs, and all 22 successful standalone programs retain `libc_left_lines=19`, despite the script saying the expected count is zero. Correction: retain and hash every linker input, make residual libc pulls fatal, report residual bytes and members, and compare complete flash, resident RAM, swap, relocation count, and startup time on identical program sets.

5. **Major -- the ABI-stability motive is reduced, not absent.** Claim: “the ABI-stability motive is absent in a one-image system” ([03-illumos.md](streams/03-illumos.md:45)). Evidence: [STORAGE.md](sys/arch/rp2040/doc/STORAGE.md:114) records a writable root and a shipped native `cc`/`smlrc`/`as`/`ld` toolchain that builds runnable programs against libc. Such user-built executables can outlive a kernel or library-only update. Correction: restrict the atomic-image argument to shipped commands, then define compatibility and rejection rules for persistent user binaries.

6. **Minor -- the text-relocation example is conditional.** Claim: a `const char * const tab[]` “forces a text relocation.” Evidence: Oracle’s [Move Read-Only Data to Text](https://docs.oracle.com/en/operating-systems/solaris/oracle-solaris/11.4/linkers-libraries/move-read-only-data-text.html) says PIC compilers can place such assignments in writable `.picdata`. Correction: say the declaration causes a text relocation only when the toolchain places relocatable pointers in a read-only segment; inspect actual sections and relocations.

7. **Minor -- `-z combreloc` is presented as an active modern switch.** Evidence: current [`ld(1):980-1009`](https://github.com/illumos/illumos-gate/blob/f0c8390bf3dce936fdac44978ddeb9c12a65f84d/usr/src/man/man1/ld.1#L980-L1009) says merging is now default and `-z combreloc` has no effect. Correction: attribute RELATIVE grouping to combined relocation sections and identify the option as historical syntax.

8. **Minor -- the 96--97% figure lacks its experimental conditions.** Evidence: Jelinek’s [prelink paper](https://people.redhat.com/jakub/prelink.pdf) reports 96.5% for one hot-cache, non-prelinked, lazy-binding run after symbol-lookup caching; the preceding run reports 98.3%. Correction: state the workload and conditions and avoid treating the ratio as a per-relocation or RP2040 estimate.

**Verdict.** The Solaris archive-removal history, libc/kernel compatibility rationale, text-relocation costs, `-z text`, immediate versus lazy binding, `isaexec`, `dldump`, and illumos’s lack of MMU-less targets survive. The stream supplies useful mechanisms, but the false multicall inventory, optional-register PIC assumption, restricted amd64 bootstrap analogy, and incomplete relink evidence prevent it from showing that fixed-address XIP libc beats either current static boxes or a relocating PIC design. The read-only review took about 5 minutes 28 seconds.
