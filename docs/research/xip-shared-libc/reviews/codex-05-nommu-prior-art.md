1. **Blocker -- The proposed experiment cannot decide which design “beats” the others.** Claim: “Deciding measurement: a board run ... reading the XIP hit and access counters” (`streams/05-nommu-prior-art.md:54-55`). The [RP2040 datasheet](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf), §2.6.3.5, printed page 125, says the counters record all XIP accesses and cache hits. They provide neither elapsed cycles nor libc attribution. They also omit executable storage, RAM consumption, and loader startup cost. **Correction:** measure cycle or elapsed time alongside counters; compare total stored bytes and peak RAM; include loader startup; control clocks, interrupts, workload output, and cold/warm cache state.

2. **Major -- The compiler-size percentages lack retained evidence.** Claim: “185 ... objects ... grew +0.8%, +2.9%, +3.6%” and GCC objects grew “+7.2%” and “+6.8%” (`stream:22-26`). `rg 'clang|fropi|frwpi|23\.1\.4|16\.2\.0|\+0\.8|\+2\.9|\+3\.6|\+7\.2|\+6\.8' measure/` returned status 1 with zero matches. Installed Clang 23.1.4 and GCC 16.2.0 verify the versions, not the results. **Correction:** retain commands, source revision, object manifest, failures, matched-object denominator, section totals, and aggregation code.

3. **Major -- Tock uses application-startup fixups and flash-resident text, not the mechanism claimed.** Claim: “elf2tab appends a relocation list the kernel applies once” and “text still runs from SRAM” (`stream:31-32,44-45`). Tock’s [`crt0.c`](https://github.com/tock/libtock-c/blob/master/libtock/crt0.c#L151-L163) sets r9 in application startup; `_c_start_pic` fixes the GOT, copies data, and applies data relocations at [lines 255-330](https://github.com/tock/libtock-c/blob/master/libtock/crt0.c#L255-L330). `app_start` explicitly names the flash address. **Correction:** call Tock flash-text PIC with application-startup relocation of RAM state. Tock supplies no evidence that the proposed relocation set is small.

4. **Major -- Two purported uncached controls still interact with the cache.** Claim: “uncached aliases at 0x11, 0x12, 0x13 prefixes” (`stream:39`). Datasheet §2.6.3.1, printed page 123, defines `0x11` as cacheable/non-allocating, `0x12` as non-cacheable/allocating, and only `0x13` as complete bypass. **Correction:** name each behavior and use `0x13` for a cache-bypass control.

5. **Major -- bFLT flags request a file mapping; they do not guarantee flash XIP.** Claim: “without RAM or GZIP flags text maps straight from the file (XIP)” (`stream:7-8`). Linux [`fs/binfmt_flat.c:528-536`](https://github.com/torvalds/linux/blob/master/fs/binfmt_flat.c#L528-L536) says the mapping “should” yield a ROM pointer but does not require one. [`mm/nommu.c:730-758`](https://github.com/torvalds/linux/blob/master/mm/nommu.c#L730-L758) defaults regular files to copied mappings and requires filesystem direct-mapping support. **Correction:** make XIP conditional on the backing file and filesystem mapping capabilities.

6. **Major -- “Every file” exceeds the fixed-address prototype.** Claim: fixed-address XIP “removes libc text ... from every file” (`stream:49-50`). Current `measure/relink-results-union.txt:7,9` reports two failed relinks; `relink-results-whole.txt:7,9,11,14` reports four. Successful rows now pass the stronger residual-byte check in `relink_against_libcx.sh:74-78`, but the tables also omit the shared image from per-program sizes. **Correction:** report 28/30 successful union relinks and 26/30 whole-libc relinks, retain failed programs outside the claim, and add the shared image once when comparing total storage.

7. **Minor -- Clang accepts address-initialized C globals under ROPI.** Claim: “ROPI rejects ... address-initialized globals” (`stream:21-22`). A Clang 23.1.4 probe using `--target=thumbv6m-none-eabi -Os -fropi` exited 0 for `const char *pointer=text` and emitted `pointer: .long text`; the C++ probe exited 1. **Correction:** distinguish C++ rejection from accepted C that still contains an address requiring relocation treatment.

8. **Minor -- The NXFLAT register statement is historical, not current.** Claim: “a GOT in r10” (`stream:35`). Current NuttX [`nxflat.rst:312-318`](https://github.com/apache/nuttx/blob/master/Documentation/os/binfmt/nxflat.rst#L312-L318) and [`Toolchain.defs:597`](https://github.com/apache/nuttx/blob/master/arch/arm/src/common/Toolchain.defs#L597) specify r9; the documentation identifies r10 as the older ABI and documents only Cortex-M3/M4 Thumb-2 toolchains. **Correction:** cite the historical r10 revision or state current r9 behavior and the unverified ARMv6-M boundary.

9. **Minor -- Four bFLT slots mean three libraries plus the executable.** Claim: “at most 4 libraries” (`stream:9`). Linux v5.17 defines four module slots at [`fs/binfmt_flat.c:72`](https://github.com/torvalds/linux/blob/v5.17/fs/binfmt_flat.c#L72), loads the executable as ID 0 at line 964, and iterates library IDs 3 through 1 at lines 1004-1010. **Correction:** say “the executable plus at most three shared libraries.”

The stream retains useful prior art: standard PIC works on Cortex-M0, GCC reproducibly rejects FDPIC on Thumb-1, and the RP2040 cache size, hit latency, flush cost, and counters match the datasheet. The architectural comparison remains unearned: compiler overhead lacks retained evidence, Tock was classified incorrectly, fixed-address coverage remains partial, and the proposed board measurement cannot compare performance, storage, RAM, and loader cost together.
