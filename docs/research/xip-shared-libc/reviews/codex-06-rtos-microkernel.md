1. **Blocker -- “Zephyr LLEXT … relocatable ELF loaded into RAM” and “runtime relocation … not worth pursuing.”** The cited comparison is dismissed without measurement. Zephyr can directly reuse persistent, read-only, relocation-free sections and supports caller-provided prelocated addresses ([llext_mem.c:128](https://github.com/zephyrproject-rtos/zephyr/blob/0c63b6bfeb0d5dc9f56a156be0248a61ab2bb6bc/subsys/llext/llext_mem.c#L128-L178), [llext.h:207](https://github.com/zephyrproject-rtos/zephyr/blob/0c63b6bfeb0d5dc9f56a156be0248a61ab2bb6bc/include/zephyr/llext/llext.h#L207-L215)). Correct the stream to distinguish copying, relocation, persistent-section reuse, and prelocation; measure the requested relocating-loader comparator.

2. **Blocker -- “Shared rodata” and software syscall-pointer verification omit the required XIP address model.** [machdep.c:920](sys/arch/rp2040/rp2040/machdep.c:920) accepts only the SRAM user window; `copyin` and `copyout` share that predicate at lines 1168-1187, and [sys_generic.c:64](sys/kern/sys_generic.c:64) rejects a flash-backed `write(2)` buffer. Flash-resident strings would therefore fail ordinary syscalls. Budget a user RX flash MPU region and separate readable-user from writable-user span validation.

3. **Major -- “Lazy libc state … if the mean untouched part is under about 1 KB, the rework does not pay.”** The threshold is unsupported, and the proposed mechanism lacks an ABI. [stdio.h:11](include/stdio.h:11) exposes `_iob` addresses, [SYS.h:35](lib/libc/arm/sys/SYS.h:35) stores through absolute `errno`, and [crt0.c:54](lib/startup-arm/crt0.c:54) owns `environ`. An MPU cannot demand-map those addresses. Specify fixed slots, accessors, or a state-base ABI, then measure peak RAM, initialization, fork, signal, and swap costs.

4. **Major -- “the freed window never lets a second process stay resident” is an invalid XIP falsifier.** [mpu.c:20](sys/arch/rp2040/rp2040/mpu.c:20) fixes every process at one address, while [vm_swap.c:62](sys/kern/vm_swap.c:62) restores each image there. Smaller text cannot create another address space. Conversely, lines 67-79 reload executable text, so XIP could reduce swap traffic without adding residency. Measure peak process RAM, swap-in traffic and latency, and flash cost separately.

5. **Major -- “heatshrink already removes the duplicates inside its window” cannot falsify cross-image pooling.** [libhsaout.c:28](tools/hsaout/libhsaout.c:28) resets the encoder, and lines 130-133 encode text and data separately for each executable. Compression history never crosses image boundaries. Compare aggregate packed blocks against the shared XIP pool plus references, veneers, and metadata.

6. **Major -- “DiscoBSD’s SVC entry avoids the wrapper hole” states an unsupported cause, and “zero successes means existing checks cover it” converts finite fuzzing into proof.** The FreeRTOS vulnerability itself raised privilege through SVC ([BAR 2023 paper, section IV-A](https://www.ndss-symposium.org/wp-content/uploads/2023/03/bar2023-23007-paper.pdf)); SVC alone supplies no immunity. Audit DiscoBSD’s complete entry, dispatch, and return path. Report fuzz coverage only for an enumerated syscall, argument, span, and direction denominator.

7. **Major -- “PIC base register (r10)” contradicts the cited NuttX branch.** Current NXFLAT uses `r9`; `r10` identifies the rejected old ABI ([nxflat.rst:361](https://github.com/apache/nuttx/blob/b2b181fbd99ad63dc83b24edcf921d826796b8db/Documentation/os/binfmt/nxflat.rst#L361-L377)). Correct the register and include the directly relevant `__nxflat_abi_v2` compatibility check.

8. **Minor -- “LZF-compressed read-only XIP filesystem” conflates flash-resident storage with instruction XIP.** CROMFS directly addresses filesystem storage but decompresses file data ([cromfs.rst:8](https://github.com/apache/nuttx/blob/b2b181fbd99ad63dc83b24edcf921d826796b8db/Documentation/os/filesystem/cromfs.rst#L8-L17)). Call it a memory-addressed compressed filesystem; the citation establishes no direct execution of compressed instructions.

9. **Minor -- “Per-process kernel data inside the swapped image” omits the existing baseline.** [vm_swap.c:104](sys/kern/vm_swap.c:104) restores `USIZE`, while lines 230-235 already save the u-area to SwapRAM or flash. Identify additional structures and quantify incremental bytes and copying rather than presenting the existing mechanism as new.

10. **Major -- provenance is not replayable.** The stream explicitly cites moving branches rather than commits, several references lack exact titles or URLs, and the measurement files changed during review. The final stable snapshots were union result `8b38f48e…` (5,632-byte rounded reservation) and whole-archive result `fbb79313…` (6,144 bytes), so “fixed 5.4 KB” names only one configuration approximately. Pin source commits, input hashes, commands, and result hashes.

The mechanism inventory survives: NuttX’s fixed userspace metadata, Zephyr’s verifier discipline, Tock’s MPU warning, F9’s fault-driven mapping, Linux’s fixed-address ABI precedent, and workspace indirection remain useful patterns. The ranking does not establish that fixed-address XIP libc beats current multicall linking or an exec-time relocating loader. A matched Cortex-M0+ experiment must compare peak SRAM, final flash blocks, exported-data ABI, pointer permissions, loader footprint, swap-in cost, and runtime latency. The bounded review took about six minutes and modified none of the reviewed files.
