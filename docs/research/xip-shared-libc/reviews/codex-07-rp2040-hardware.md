1. **Blocker -- the LARGE-epoch MPU defect is real.** Claim: “A P_LARGE stack therefore lies in 0x20024000 to 0x20028000, which no enabled region grants.” `swapram.c:730-733` raises `USER_TOP` to `0x20028000`; `mpu.c:130-136,187-195` grants SRAM only through `0x20024000` and disables regions 4-7. `DS:6483-6492` restricts `PRIVDEFENA` to privileged accesses. Most decisively, `MPU.md:210-227` records a four-region board run faulting on `0x20024000`. Correction: dynamically enable a read-write region for `[0x20024000,0x20028000)` only while the SwapRAM pool is evacuated and the LARGE epoch owns those bytes; disable and read back that region before reopening the pool. Add a combined MPU-plus-LARGE board gate.

2. **Major -- the proposed falsifier measures the wrong quantity.** Claim: “an image between 144 and 160 KB ... that completes” refutes the defect. LARGE admission uses resident text, data, BSS, heap, argument-dependent stack, and environment sizes (`exec_aout.c:190-197`; `exec_subr.c:434-451`), not executable-file size. `machdep.mpu.enable` reports cached initialization state (`mpu.c:198,233-237`). Correction: record exact kernel and executable hashes, computed resident demand, `P_LARGE`, entry stack pointer, current MPU region readback, and successful unprivileged reads and writes inside the bonus interval.

3. **Minor -- “the first unprivileged push faults” is not universal.** `ARG_MAX=5120` (`sys/sys/syslimits.h:36`). The reproduced maximal-empty-argument case yields `stack.len=27664`, stack base `0x200213f0`, and resident demand `158664`; retained `lib/crt0.o` begins with `push {r4,lr}`, which lands below `0x20024000`. Its first argument string lies at `0x20026bf8` and faults later. Correction: say the enlarged stack and argument area intersects denied SRAM; the first denied instruction depends on the argument layout.

4. **Minor -- existing LARGE evidence needs explicit chronology.** `tests/rp2040/swapram_large/bigtest.c:2-77` and `TESTING.md:1539-1545` exercise LARGE execution, but omit MPU assertions. `memory-ownership-plan.md:295-298` records successful board runs introduced September 13; `git log -S` places MPU initialization on September 20. Correction: state that retained LARGE successes predate MPU protection and therefore supply no counterexample.

5. **Major -- “XN on user data | not possible” confuses current layout with architectural capability.** `DS:5485-5488,6580-6594` defines higher-priority overlapping regions and XN; `mpu.c:187-190` leaves four regions available. Correction: classify XN as unsupported by the current static map and OMAGIC loader. Aligned overlays can protect stack/data portions; complete separation requires executable/data bounds, padding, and region-budget analysis.

6. **Major -- the user-stack guard cost is overstated.** Claim: “costs 256-511 window bytes.” A 256-byte region has eight 32-byte subregions (`DS:6588-6594`), exactly the mechanism already used in `mpu.c:117-127`. Arithmetic gives 32 guard bytes plus at most 31 alignment bytes, or 32-63 bytes. Correction: analyze a higher-priority 32-byte no-access subregion and its required updates when the break moves.

7. **Major -- DMA is rejected against an unrelated denominator.** Claim: “copy payoff about zero against 190 ms flash writes per swap.” `zswap.md:123-132` extrapolates write latency, while `DS:9142-9155,9169-9186` describes streaming and DMA for reads concurrent with execution. Correction: measure exec, swap-in, filesystem-read, copy, and CRC workloads separately; write latency cannot bound read-side benefit.

8. **Major -- “20-40x slower” is not a workload measurement.** `DS:9027` gives a one-cycle cache hit; `boot2_w25q080.S:99-124` supports roughly 40 clocks for an isolated miss transfer. Neither establishes whole-kernel slowdown. Correction: report that transfer estimate and measure elapsed workload time plus both XIP access and hit counters. A hit-count delta alone also fails to establish line 56’s “cheap speed gain.”

9. **Minor -- “WFE useful only with core1” is false.** `DS:4803-4817` names hardware interrupts, pending exceptions under `SEVONPEND`, asynchronous exceptions, and debug events. Correction: describe WFE as an unmeasured single-core alternative for event-driven waits.

10. **Minor -- “220 free” overstates the stack watermark.** `CAPACITY.md:138-144,186-203` says the measurement sees overwritten words, misses reserved-but-unwritten frames and sentinel collisions, and omits required fault, signal, and SwapRAM workloads. Correction: report “220 untouched sentinel bytes in the retained workload.”
